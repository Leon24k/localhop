localhop Technical Documentation

This manual explains how to install, configure, operate, and troubleshoot the localhop CLI client and the localhop relay server.

1. Overview

localhop exposes a local HTTP or WebSocket server to the public internet. The system uses Rust binaries with no garbage collector.

The system has three components:

  • localhop-server: A public Axum relay server that receives internet requests and sends them through an open tunnel.
  • localhop: A local CLI client that opens one persistent WebSocket tunnel to the relay server and forwards traffic to localhost.
  • Live Inspector: A local web interface on port 4040 that shows live HTTP traffic and replays saved requests.
Note

All examples in this manual assume localhop version 0.1.0.

3. Installation

Select one installation method for your environment.

Method A: Install with Cargo

  1. Open a terminal window.
  2. Run this command to install from crates.io:
cargo install localhop

To install directly from the GitHub repository, run this command:

cargo install --git https://github.com/Leon24k/localhop localhop

Method B: Install with npm or npx

Use this method if your machine does not have Rust installed.

  1. Run localhop directly with npx:
npx localhop 3000 --server https://your-relay.onrender.com
  1. Or install the package globally:
npm install -g localhop

Method C: Install with the Shell Script (macOS and Linux)

  1. Run this command to download the release binary to ~/.local/bin:
curl -fsSL https://raw.githubusercontent.com/Leon24k/localhop/main/scripts/install.sh | sh
  1. Check that the binary works:
localhop --version

4. Quick Start Procedure

Follow these steps to test a full tunnel on your local computer.

  1. Open Terminal 1 and start the relay server:
cargo run --release -p localhop-server
  1. Open Terminal 2 and start a sample HTTP server on port 3000:
python3 -m http.server 3000
  1. Open Terminal 3 and open a tunnel to port 3000:
cargo run --release -p localhop -- 3000 -s demo
  1. Open http://127.0.0.1:8080/t/demo in your browser to reach your local server.
  2. Open http://127.0.0.1:4040 in your browser to see live requests in the inspector.
Note

Press Ctrl+C in any terminal to stop the process safely.

5. CLI Reference (localhop)

Use the localhop command to connect a local service to a relay server.

localhop <PORT> [OPTIONS]
Flag / Argument Environment Variable Default Function
<PORT> None Required Sets the local port that receives forwarded traffic.
--host <HOST> None 127.0.0.1 Sets the local host address for the target service.
--server <URL> LOCALHOP_SERVER ws://127.0.0.1:8080 Sets the relay server URL. Accepts http, https, ws, or wss.
-s, --id <ID> None Random 8 chars Requests a fixed tunnel ID. Use 3 to 32 lowercase letters, digits, or hyphens.
--token <SECRET> LOCALHOP_AUTH_TOKEN None Sends the shared secret token to a private relay server.
--basic-auth <U:P> LOCALHOP_BASIC_AUTH None Protects the public URL with HTTP Basic Auth at the relay edge.
--preserve-host None false Keeps the incoming Host header instead of setting <host>:<port>.
-q, --quiet None false Hides per-request access log lines in the terminal.
--inspector-port <P> None 4040 Sets the local port for the web inspector interface.
--no-inspector None false Stops the CLI from starting the local web inspector server.

6. Relay Server Reference (localhop-server)

Run localhop-server on a host with a public URL or IP address.

Flag Environment Variable Default Function
--bind <IP> LOCALHOP_BIND 0.0.0.0 Sets the network interface address to listen on.
-p, --port <PORT> PORT 8080 Sets the single HTTP and WebSocket port.
--public-url <URL> LOCALHOP_PUBLIC_URL Auto Overrides the detected public base URL for path-routed tunnels.
--base-domain <DOM> LOCALHOP_BASE_DOMAIN None Enables wildcard subdomain routing at <id>.<domain>.
--auth-token <TOK> LOCALHOP_AUTH_TOKEN None Requires CLI clients to send this exact token on connect.
--timeout-secs <S> LOCALHOP_TIMEOUT_SECS 60 Sets the maximum wait time for an upstream response header.
--max-tunnels <N> LOCALHOP_MAX_TUNNELS 1000 Sets the maximum number of simultaneous active tunnels.
--max-body-bytes <B> LOCALHOP_MAX_BODY_BYTES 52428800 Sets the maximum HTTP request body size (50 MiB default).
--idle-timeout-secs LOCALHOP_IDLE_TIMEOUT_SECS 45 Closes silent or dead tunnel connections after this timeout.

Built-In Relay Endpoints

  • GET /: Shows live relay status, active tunnel count, and total proxied requests.
  • GET /_localhop/health: Returns JSON health metrics for load balancers and Render health checks.
  • GET /_localhop/ws: Accepts WebSocket tunnel connections from the CLI client.
  • ANY /t/{id} and ANY /t/{id}/{*rest}: Routes public traffic to the matching tunnel.

7. Live HTTP Inspector

When the CLI starts, it opens a local web server at http://127.0.0.1:4040. The server keeps the latest 200 requests in a bounded ring buffer and caps each body preview at 128 KiB.

Replay a Captured Request

  1. Open http://127.0.0.1:4040 in your browser.
  2. Click a request row in the left list.
  3. Click Replay to send the exact request to your local server again.
  4. Or click Edit & Replay to change the method, path, headers, or body before you send it.

Export and Replay Offline Fixtures

  1. Select a captured webhook request in the inspector.
  2. Click Export JSON to save the request as a local .json file.
  3. Later, click Import in the top toolbar and select the saved file.
  4. The inspector immediately sends the saved request to your local server, even if the remote relay is offline.
Note

The inspector binds only to 127.0.0.1. It checks the HTTP Origin header on POST /api/replay and POST /api/clear to block cross-origin browser requests.

8. WebSocket Passthrough

localhop supports bidirectional text and binary WebSocket connections through the same multiplexed tunnel. You do not need extra flags to enable this feature.

When a public client sends an Upgrade: websocket request:

  1. The relay server sends a WsOpen frame to the CLI client.
  2. The CLI client opens a WebSocket connection to your local server.
  3. The CLI client sends a WsOpened confirmation frame back to the relay server.
  4. Both sides stream text and binary frames in real time until either side closes the socket.

This mechanism supports Vite HMR, Next.js Fast Refresh, Socket.IO, and custom WebSocket applications.

9. Relay Deployment

Deploy on Render (Free Tier)

  1. Fork or push the localhop repository to your GitHub account.
  2. Open the Render dashboard and click New → Blueprint.
  3. Select your repository. Render reads render.yaml and builds the multi-stage Dockerfile.
  4. Set LOCALHOP_AUTH_TOKEN in the Render environment settings to keep your relay private.
  5. Connect your CLI to the Render URL:
export LOCALHOP_SERVER=https://your-service.onrender.com
export LOCALHOP_AUTH_TOKEN=your-secret-token
localhop 3000

Deploy with Docker

  1. Build the container image:
docker build -t localhop-server .
  1. Start the container:
docker run -d -p 8080:8080 \
  -e LOCALHOP_AUTH_TOKEN=your-secret-token \
  -e LOCALHOP_MAX_TUNNELS=500 \
  localhop-server

Enable Wildcard Subdomain Routing

  1. Create a wildcard DNS record (for example, *.hop.example.com) that points to your relay server.
  2. Configure HTTPS termination (for example, Caddy, Nginx, or Cloudflare) in front of port 8080.
  3. Start the relay server with LOCALHOP_BASE_DOMAIN=hop.example.com.

10. Binary Protocol Specification

All frames travel inside WebSocket binary messages. Byte 0 identifies the frame type. Payload frames carry raw bytes without base64 or JSON encoding.

Tag Frame Name Wire Layout Direction
0x01Hello[tag][JSON]CLI → Relay
0x02Welcome[tag][JSON]Relay → CLI
0x03Error[tag][JSON]Relay → CLI
0x04RequestHead[tag][JSON]Relay → CLI
0x05RequestBody[tag][req_id: 8B BE][raw Bytes]Relay → CLI
0x06RequestEnd[tag][req_id: 8B BE]Relay → CLI
0x07ResponseHead[tag][JSON]CLI → Relay
0x08ResponseBody[tag][req_id: 8B BE][raw Bytes]CLI → Relay
0x09ResponseEnd[tag][req_id: 8B BE]CLI → Relay
0x0APing[tag][ts_us: 8B BE]CLI → Relay
0x0BPong[tag][ts_us: 8B BE]Relay → CLI
0x0CWsOpen[tag][JSON]Relay → CLI
0x0DWsOpened[tag][JSON]CLI → Relay
0x0EWsMessage[tag][req_id: 8B BE][is_bin: 1B][raw Bytes]Bidirectional
0x0FWsClose[tag][req_id: 8B BE]Bidirectional

11. Security Controls

Caution

Do not run an unauthenticated relay on the public internet without a token. Unknown users can open tunnels and consume your server bandwidth.

Caution

Always terminate TLS (HTTPS and WSS) in front of a public relay server. Plain HTTP exposes Basic Auth headers, auth tokens, and application payloads in transit.

  • Constant-Time Verification: The relay server compares LOCALHOP_AUTH_TOKEN and --basic-auth headers in constant time.
  • Edge Basic Auth: The relay server rejects unauthorized requests with HTTP 401 before they cross your tunnel.
  • Reverse-Proxy Headers: The relay server sets X-Forwarded-Proto, X-Forwarded-Host, X-Forwarded-For, and X-Localhop-Tunnel-Id.
  • Resource Caps: Use --max-tunnels, --max-body-bytes, and --idle-timeout-secs to limit memory and bandwidth per relay instance.

12. Troubleshooting

Use this fault-isolation table to solve common operational errors.

Symptom / Error Possible Cause Corrective Action
502 Bad Gateway: could not reach local server No local application listens on the target port. Start your local dev server and check that the port number matches localhop <PORT>.
unauthorized: invalid or missing auth token The relay requires LOCALHOP_AUTH_TOKEN, or the tokens do not match. Pass the correct token with --token or export LOCALHOP_AUTH_TOKEN.
tunnel id '...' is already in use Another active CLI session holds that custom ID. Stop the older session, wait 45 seconds for idle eviction, or choose a different -s ID.
413 Payload Too Large The incoming HTTP request body exceeds --max-body-bytes. Increase LOCALHOP_MAX_BODY_BYTES on the relay server.
401 Unauthorized on tunnel URL The tunnel owner enabled --basic-auth. Send valid HTTP Basic Auth credentials in the browser prompt or request header.
could not bind inspector on port 4040 Another process uses port 4040. Pass --inspector-port 4041 or disable the UI with --no-inspector.
